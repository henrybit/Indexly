# Indexly

**Indexly** 是面向 Elasticsearch 7.x / 8.x 的轻量桌面索引管理工具。在本机连接集群、快速检索索引、在防护下删除，并用「先预览、再清理」的 TTL 规则治理过期索引。

[English](README.md) · [使用说明](USER_GUIDE.md) · [产品说明](PRODUCT.md) · [开发文档](Develop.md)

---

## 为什么选 Indexly

Indexly **不是** Kibana 的替代品，也不覆盖可视化看板、Discover 或完整集群运维。它专注索引生命周期里最高频、也最容易误操作的环节：

- 多套集群配置一键切换，不用反复填写
- 在大集群中快速找到目标索引
- 只删除你明确勾选的索引
- 过期清理前先预览匹配结果

支持 **Windows**、**macOS**、**Linux**，本地直连目标集群，无需额外部署管理服务。

## 功能

### 多集群连接

- 保存多套连接配置，一键切换当前活跃集群
- 支持 HTTP / HTTPS
- 支持 Basic Auth
- 可选跳过证书校验，方便自签证书或内网测试环境
- 连接后展示集群名称与版本，并对非 7 / 8 主版本给出提示
- 连接配置保存在本机；过期规则按集群隔离

### 索引检索与浏览

- 按索引名搜索，支持 `*` / `?` 通配符（如 `log-*`、`index_?`）
- 列表展示健康状态、开关状态、分片、文档数、存储体积等
- 适合先定位目标，再执行删除或清理

### 安全删除索引

- 勾选一个或多个索引后删除，并二次确认
- **禁止** `*`、`_all` 等危险全量删除方式
- 必须显式勾选具体索引，降低误删风险
- 结果区分成功 / 失败，便于排查权限或只读块等问题

### 索引过期治理（TTL）

- 规则按**当前集群**分别保存
- 使用正则匹配索引名
- 保留时长支持天 / 小时，依据索引创建时间判断是否过期
- 可跳过以 `.` 开头的系统索引
- 规则可启用、停用、编辑、删除
- **预览匹配**：先看命中与过期列表
- **清理过期**：仅删除已过期且命中规则的索引，并再次确认

## 产品特点

| | |
| --- | --- |
| **轻量桌面端** | 本地运行，直连集群，无需额外控制面 |
| **安全优先** | 危险操作确认、禁止全量删除入口、TTL 先预览后执行 |
| **多环境切换** | 开发 / 测试 / 生产配置并存，不用反复改表单 |
| **跨平台一致** | Windows、macOS、Linux 同一套工作流 |
| **聚焦索引治理** | 连接 → 检索 → 删除 / 过期清理，链路清晰 |

---

## 典型场景

1. **日常排障** — 用通配符快速找到异常或占用过大的索引  
2. **环境切换** — 在多套测试 / 预发集群间切换  
3. **日志清理** — 为 `logs-YYYY.MM.DD` 类索引配置 7 天保留，预览后清理  
4. **误删防护** — 删除时强制确认具体索引名，避免通配符误伤  

---

## 当前不做的事

- Kibana 级可视化、Discover、Dashboard
- 任意 Query DSL / SQL 查询控制台
- 完整节点、分片分配、ILM Policy 运维面板
- 云端账号或远程策略同步（数据均在本机）
- 企业级密钥托管 — 请保护存放凭据的操作系统账户
